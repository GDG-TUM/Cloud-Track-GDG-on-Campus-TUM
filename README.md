A practical engineering programme for students who want to understand how software systems are built, deployed and operated in the cloud. Beginners are welcome; students with prior experience get meaningful extension work.

## Start here
1. Read the [programme guide](curriculum/README.md).
2. Complete [Getting Started](GETTING-STARTED.md), including account safety and tool setup.
3. Follow the [16-week roadmap](curriculum/roadmap.md).
4. Choose or join a [capstone project](projects/README.md).
5. Complete each weekly guide and submit evidence at its checkpoint.

## The 16-week journey
| Phase | Weeks | Focus | Evidence |
|---|---:|---|---|
| Understand the system | 1–4 | Cloud concepts, Linux, networking, Git | Safe setup, CLI/network exercises, reviewed PR |
| Build and deploy | 5–8 | Application runtime, Docker, Google Cloud, Cloud Run | Containerized application deployed |
| Engineer for production | 9–12 | Data, cloud networking, CI/CD, Terraform | Data-backed app, automated pipeline, IaC |
| Operate and demonstrate | 13–16 | Security, observability, reliability, capstone | Reviewed, observable project and technical demo |

## Graduate outcomes
Members completing the core pathway should be able to explain cloud fundamentals; use Linux, networking tools and Git; build and containerize a small application; deploy it to Cloud Run; connect data services; automate checks with GitHub Actions; provision basic infrastructure with Terraform; apply IAM and secrets-management fundamentals; inspect logs and metrics; and document and present a cloud project.

## How the programme works
- One facilitated session each week, approximately 90 minutes.
- A guided lab and a core challenge.
- Approximately 2–3 hours of independent practice each week.
- Evidence through code, diagrams, command output, explanations or a demo.
- Peer review and help are part of the learning process.

Every week has a beginner core path and an intermediate stretch challenge.

## Safety and cost
Cloud services can incur charges. Check current pricing, quotas and eligibility before provisioning resources. Budget notifications are not spending caps. Prefer local alternatives where possible and delete temporary resources after each lab. Never commit credentials, service-account keys, tokens or environment files.

Google Cloud is the teaching platform; engineering concepts transfer to other providers. This is an introductory learning programme, not a professional certification or a guarantee of production readiness.

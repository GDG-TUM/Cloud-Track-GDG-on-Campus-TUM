# Cloud Engineering Curriculum

[← Back to Cloud Track home](../README.md)

**Duration:** 16 weeks · **Audience:** mixed beginner-to-intermediate cohort · **Platform:** Google Cloud with transferable engineering fundamentals.

This is the authoritative curriculum. Weekly guides, member roadmaps and instructor plans should align with this sequence. The older 10-week pilot materials in weekly-sessions remain available as historical resources; they are not the source of truth for this programme.

## Who this is for
- **Beginners:** no previous cloud or Linux experience is required. Follow the core path, use command examples and ask for help early.
- **Intermediate learners:** complete the same outcomes, then take extension challenges, investigate trade-offs, add tests and review peers' work.
- **Everyone:** programming familiarity helps from Week 5 onward. New developers can use a small starter app or pair with a teammate; the focus remains cloud engineering.

## Programme outcomes
1. Describe cloud service models, regions/zones, shared responsibility, resource hierarchy and cost controls.
2. Use Linux, shell tools, SSH and Git for routine development tasks.
3. Explain DNS, HTTP(S), IP addressing, ports, routing, subnets and firewall behaviour.
4. Build and configure a small application suitable for deployment.
5. Build, run, inspect and publish a Docker image.
6. Deploy a containerized application to Cloud Run.
7. Select and connect appropriate storage and database services.
8. Explain cloud network boundaries and service connectivity.
9. Automate quality checks and deployment workflows with GitHub Actions.
10. Provision and safely destroy basic infrastructure with Terraform.
11. Apply IAM least privilege, secrets handling and baseline security controls.
12. Use logs, metrics and alerts to investigate application behaviour.
13. Communicate architecture, trade-offs, operational risks and project outcomes.

## Four phases
| Phase | Weeks | Theme | Exit gate |
|---|---:|---|---|
| 1 | 1–4 | Understand the system | Work in a terminal, explain a network request and collaborate through Git |
| 2 | 5–8 | Build and deploy | Containerized application runs on Cloud Run |
| 3 | 9–12 | Engineer for production | Data services, automated delivery and reproducible infrastructure |
| 4 | 13–16 | Operate and demonstrate | Security-reviewed, observable capstone presented with evidence |

## How to use this curriculum
1. Read the weekly guide before the session.
2. Complete the **core path** first; it defines the expected outcome for everyone.
3. Attempt the **stretch path** if you already understand the basics or finish early.
4. Record evidence in your project repository or learning log.
5. Complete the checkpoint and ask for help if blocked for more than 30 minutes.
6. Keep cloud resources only when needed and follow cleanup instructions.

**Weekly cycle:** Understand → See → Build → Extend → Prove → Clean up.
